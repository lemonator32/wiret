## Appendix E. Changes in Draft 0.6

Draft 0.6 changes three pieces of surface syntax to make graphs easier to read. The model, the bytecode and the semantic hash of a graph are unchanged; only the text changes.

| Change | Detail | Section |
| --- | --- | --- |
| `::<` for generics | Every generic argument list is introduced by `::`: node type arguments (`Add::<i32>`), declaration type parameters (`macro ForEach::<T>`) and generic types (`array::<i32>`, `map::<K, V>`). A node line binds an id to a kind, so with a bare `<` a node like `NodeType<a, b> variable` could read as a comparison. The old form is a syntax error whose message shows the new one. | 2.1, 2.2, 2.3, 3 |
| Inputs below the node | Inputs are no longer written like call arguments (`Add<i32>(a: x, b: y)`). Each one is its own line below the node line, `.pin <- value`, indented one level further. `<-` mirrors the `->` of exec wires. Every input of a node can be read down one column, and rewiring one input changes exactly one line. Node lines no longer wrap (canonical rule 7). | 2.3, 2.5, 2.6 |
| `#[...]` for metadata | Attributes that never change compiled output are written `#[name(...)]` on their own line above what they describe: `#[doc]`, `#[category]`, `#[keywords]`, third-party and unsafe attributes. `@` is kept for semantic attributes (`@pure`, `@count(n)`, `@id`), which end the line they modify; an unknown `@` name is `E0104`, and `@doc` and the other old forms get a message showing the new one. The semantic hash strips every `#[...]` line without needing a list of names. | 2.1, 2.4, 2.5, 3.5, 4.7, 5.4, 7.2 |
| Notes replace the `markup` block | `attribute id on target = Note(message: "...")` becomes `#[note("...")]` above its node, box or declaration, and the `markup` block and the keywords `markup`, `attribute` and `on` are removed. Each note is still its own line, so rewording one cannot conflict with an edit to its target. Notes need no ids: they merge as a list keyed by text (section 7.1). The Draft 0.4 guarantee that a note outlives its target is kept by moving it to the enclosing graph as `#[note("...", detached: "id")]` (`W0604`). `--convert-comments` now leaves each converted comment where it was written. | 2.1, 2.3, 2.4, 2.6, 4.7, 7.1, 7.2, 7.5 |
