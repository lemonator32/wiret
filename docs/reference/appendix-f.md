## Appendix F. Changes in Draft 0.7

Draft 0.7 records decisions made while adding structs and enums to the prototype, where the draft was silent or did not fit a struct that lives outside a class. The table lists each change and where it is.

| Change | Detail | Section |
| --- | --- | --- |
| Member order is kept | Struct fields and enum members keep the order they are written in. The canonical form never sorts them, because field order is the struct's layout and member order decides the value of a member written without `= INT`. Reordering them changes the semantic hash. | 2.2, 2.5 |
| Enum values `Mode.Chase` | An enum value is written as the enum's name, a dot and a member: on a pin (`.mode <- Mode.Chase`), as a default (`mode: Mode = Mode.Idle`) and in `@cases(Mode.Idle, Mode.Chase)`. On a pin it has the shape of a pin reference; it is the enum value when the graph has no node with that id, and a node id that is also an enum's name is `E0102`, so the reading never depends on intent. A member without `= INT` is one more than the member before it, and the first is 0. | 2.1, 2.2, 2.3, 2.4 |
| Struct nodes name their struct | `MakeStruct Vec2` and `BreakStruct Vec2` name the struct; `GetField Vec2.x` and `WithField Vec2.x` name the struct and the field. Outside a class method nothing else on the node says which struct it is. A class field keeps the bare form, `GetField health`. | 2.3, 3.3 |
| Struct node pins | `MakeStruct` has one input per field, in declaration order, and the output `result`; an unbound input takes the field's default, so it never warns `W0201`. `BreakStruct` has the input `obj` and one output per field, matching `GetField` and `WithField`. | 3.3 |
| Struct reads are pure | `GetField` and `BreakStruct` on a struct are `pure`, also in a `@pure` function: a struct is a value, so reading one cannot see a change (section 4.3 already let struct arguments be read freely). `reads` purity applies to `GetField` on a class reference. `SetField` on a struct is `E0501`, pointing to `WithField`. | 3.3, 4.3 |
| Struct defaults | The default value of a struct holds each field's declared default, else that field type's default. Field defaults are written into the `5F` type entry, so the VM builds struct locals and globals from it and the compiler builds the same value for an unbound struct pin. | 3.1, 5.3 |
| Struct equality | `Eq` and `Ne` on structs compare field by field, in declaration order, with each field's own equality (so a struct holding NaN is not equal to itself). They compile inline to `struct.get` and the field comparisons. | 4.9 |
| Enum conversions | `Convert` goes between an enum and its own underlying type only; reaching another integer type takes a second `Convert`. | 3.2 |
| Diagnostics | New `E0503`: a struct holds itself by value, directly or through other structs. `E0102` also covers duplicate fields and members, a struct or enum named like a built-in type, and a node id that is also an enum's name. `E0110` also covers a field default, an enum member value or a `@cases` value that does not fit its type. | 2.2, 2.4, 4.7 |
| Verifier | Structure checks that no struct type holds itself by value, directly or through other structs. Type references may point to later entries, which `struct Tree { children: array::<Tree> }` needs. | 5.5 |

**Considered and not adopted.** `GetField::<Vec2> x`: type arguments name types a node is generic over, while here the struct is the thing the node acts on, which is what a symbol is for, and `Vec2.x` reads like `Mode.Chase`. Taking the struct type from whatever is wired to `obj`, as the class example in section 2.6 can: a node's pins would then depend on its wiring, so a fresh, unwired node would have none. A `std.struct.Equals` native for struct equality, as containers use: a native has one fixed signature, so it would need one native per struct type.
