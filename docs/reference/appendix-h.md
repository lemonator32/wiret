## Appendix H. Changes in Draft 0.9

Draft 0.9 changes how node statements are written, following the research note *Making the Asymmetry Work: Text Syntax for a Blueprint-Style VPL* (`docs/research/`). That note observes that a data input has exactly one source, so read backwards from the inputs a graph's data wires form a tree that nested expressions can show, and only a shared output breaks it. The draft takes the part of that design that fits Wiret's node model, nesting single-use data nodes, and keeps named nodes for everything else.

| Change | Detail | Section |
| --- | --- | --- |
| Inputs in parentheses | A node's inputs are written in parentheses after it, separated by commas, with a trailing comma allowed: `Call host.Log(.message <- "hi")`. The canonical form puts one input per line, each with a trailing comma, and the `)` on a line of its own. Draft 0.6 wrote each input on its own line below the node with no delimiters, so where a node ended depended on the next line's first character. | 2.1, 2.3, 2.5 |
| Empty parentheses | A node with no bound inputs is written `Entry()`, `GetLocal score()`. Every node statement now has the same shape, which is what lets a node be written inside another node's input. | 2.3, 2.5 |
| Node metadata in the layout block | A node's `#[note]`, `#[doc]` and other metadata lines stand above the node's line in the layout block, not above the node statement. A node with metadata and no position is listed by name alone. Node statements now hold only what changes compiled output, and rewording a note can never touch the lines of the node it explains. | 2.3, 2.4, 2.5 |
| Inline nodes | A node that exactly one input reads, that has no exec pins and that carries no semantic attribute is written inside that input, followed by the output it feeds in: `.message <- Call std.string.Concat(...).result`. It is named by its position, its consumer's name, a dot and the input (`show.message`), and that name is used in the layout block, in box members, in diagnostics and in edit requests. The reader also accepts such a node declared by name; the formatter writes it inline. An inline node that comes to feed a second input is declared, its dots turned into underscores (`show_message_b`). | 2.3, 2.5 |
| Inline names are not identities | An inline node's name changes when the node moves to another input, and another node may later be written at the same position, so inline names are never recorded in `wiret.ids` and never `E0140`. | 2.3, 7.3 |
| Function flags | The verifier rejects a function entry with flag bits other than pure, latent and event, and an event that is not latent or that has results. A fuzz test found that the VM could be handed an "event" with results and crash when it ran it. | 5.2, 5.5 |

**Considered and not adopted.** The research note's other mechanisms solve problems this model does not have, or have not been tried yet. *Structural deduplication* (merging identical pure expressions) is lossy: two nodes drawn apart would collapse into one, and it is unsafe for anything that reads state. *Positional back-references* (`^`) change meaning when a line is inserted. An *implicit-parameter block* (`expr => { ... it ... }`) for shared outputs, and *structured continuation* for exec fan-in, would remove node ids altogether; Wiret keeps them, because ids are the identity diffs, merges, notes, breakpoints and `wiret.ids` key on (sections 2.3, 7.1, 7.3). A shared output is therefore still a declared node, whose id is the name it is shared under, which is the research note's fallback *tag* with a name the author chose.

**Trade-offs to watch.** Moving a node between inline and declared moves its lines, so wiring a single-use node into a second input shows as a larger diff than in Draft 0.8. Inline names follow positions, so an edit that moves a node to another input renames it; a merge matches inline nodes by position. Whether this costs more in reviews and merges than nesting gains in readability is a question for the review trial of section 9.1.
