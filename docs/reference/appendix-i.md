## Appendix I. Changes in Draft 0.10

Draft 0.10 follows a review of the language as of Draft 0.9. It takes the changes that cost little and remove a way for a correct-looking graph to fail: a fault in a value nobody chose, a value read where it was never produced, a hand edit that made a file unreadable, and two spellings for one field. All of them are implemented in the prototype with tests. Like the inline nodes of Draft 0.9, the qualified member names change the canonical form; that is a major-version change once the format is frozen (section 8), and is made here while the format is still a draft.

| Change | Detail | Section |
| --- | --- | --- |
| Lazy `Select`, `And`, `Or` | `Select` evaluates `cond` and then only the input it chooses; `And` and `Or` evaluate `b` only when `a` does not decide the result. A fault in an input that is not demanded is never raised, so `Select(cond: i < length, a: ArrayGet(arr, i), b: 0)` is safe. Blueprints evaluate every input of these nodes. The compiler lowers them to branches; pure inputs around them are evaluated into temporaries first, so every branch target starts on an empty operand stack as the verifier requires. | 3.3, 4.3 |
| `E0310` replaces `W0310` | Reading an impure output that its producer does not dominate (after a join, or before the producer can have run) is an error instead of a warning that the value may be zero. The fix is the existing idiom: store the value in a local on every path. No lesson, example or `std` macro read such a value. The bytecode keeps its meaning for such a read, since the verifier does not check dominance. | 4.2, 4.3, 4.7 |
| Stale layout lines are kept (`W0605`) | A layout line, or metadata above it, whose name is not a node of the graph was a syntax error. A hand edit that moves an inline node changes its dotted name, so editing a node statement could make the layout block unreadable. Such lines are now kept as written, through the formatter, the editor and a merge, and reported until they are renamed or deleted. | 2.3, 4.7 |
| Promotion skips taken and retired ids | An inline node that comes to feed a second input is declared as its dotted name with underscores, then `_2`, `_3`, ... past the ids of other nodes and, in a project, past the graph's node ids retired in `wiret.ids`, so a promotion never produces a duplicate or an `E0140`. | 2.3, 7.3 |
| Class members are written qualified | `GetField Player.health`, `SetField Player.health`, `Broadcast Player.OnHit` and `ArrayAdd::<i32> Player.items` are the canonical form everywhere, so a node reads the same inside a method and outside one. The bare name is still read inside a method of the member's class and is written qualified with that class. | 2.3, 3.3 |
| Table cleanup | Every code and attribute in the reference tables is set in code font, and the diagnostics table is sorted by code. | 2.4, 3.3, 4.7 |
