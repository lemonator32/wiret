## Appendix J. Changes in Draft 0.11

Draft 0.11 takes the readability changes from the review that led to Draft 0.10. Each one removes text that said nothing a reader needed, or lets the text say something it could not keep before; none changes what a program does. All of them are implemented in the prototype with tests. They change the canonical form, which, as in Drafts 0.9 and 0.10, is a major-version change once the format is frozen (section 8) and is made here while the format is a draft. Every file in the prototype's lessons, examples and standard library was reformatted with `wiretc fmt`.

| Change | Detail | Section |
| --- | --- | --- |
| Implied output | An inline node with one data output feeds that output in without naming it: `.message <- Convert::<i32, string>(...)`, not `(...).result`. A node with several outputs still names the one it feeds in, and leaving it out is a syntax error that lists them. The reader accepts the output written out, and the formatter leaves it out. Most `.result` and `.value` suffixes in the lessons are gone. | 2.3, 2.5 |
| Expression bodies | A `func` outside a class with one result may be written `func Clamp01(v: f32) -> (result: f32) @pure = Min::<f32>(...)`, with its parameters named bare. It is notation for an `Entry` wired to a `Return`, so the model, the bytecode and the semantic hash are those of that graph. The canonical form uses it when the graph has that shape and nothing else to keep, such as a layout block; once an editor places the nodes, the function is written with braces. | 2.2, 2.3, 2.5 |
| `Format` | `Format "{n} squared is {sq}"(.n <- ..., .sq <- ...)` builds text from a template. Each placeholder is an input that takes a `bool`, a number or a string and writes it as `Convert` would. It replaces a stack of `Concat` and `Convert` nodes, often eight lines with three, and compiles to the same calls. | 2.3, 3.3 |
| Flow block first | In canonical form a body is its locals and states, its `flow` block, its node statements and its layout block, in that order, so a graph reads as the order in which it runs and then the nodes. Node statements stay sorted by id for merges; `wiretc view --flow` still puts them in flow order too. | 2.3, 2.5 |
| Attached comments | A `//` comment directly above a declaration, a member, a `local` or `state`, a node statement, an input binding or a flow wire is part of the model: written back in place, merged as a field of its element, and outside the semantic hash. A node with a comment is declared, never written inline. Only a comment attached to nothing is still trivia, reported as `W0603` with the same convert-or-drop choice. | 2.1, 2.5, 7.1 |
