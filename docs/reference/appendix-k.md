## Appendix K. Changes in Draft 0.12

Draft 0.12 takes the changes from the review of Draft 0.9 that needed more design than the others: snapshots of mutable state, an early exit from a loop, enum values that cannot be read as wires, and keywords that no longer take common words away. All of them are implemented in the prototype with tests. The enum spelling changes the canonical form, which, as in the drafts before it, is a major-version change once the format is frozen (section 8) and is made here while the format is a draft. `cont.depth` (17) and `cont.trunc` (18) are new instructions in WBC 1, which is also still a draft.

| Change | Detail | Section |
| --- | --- | --- |
| `E0320` and `@live` | `W0320` becomes an error, and is narrowed so that it fires only when it matters: a `reads` node is evaluated again at two impure consumers that can run one after the other in one call. Consumers on exclusive branches do not conflict; a loop's body, its next pass and its `done` chain do. The fix is a local, which takes a snapshot, or `@live` on the node when each consumer should see the current value. The check found a real bug in a prototype test: a method that stored `hp - amount` and then returned it read `hp` again and subtracted twice. `DoN`'s `counter` reads the count after incrementing it on purpose, and is now marked `@live`. | 2.4, 4.3 |
| `Leave` and `break` | `Leave o` is `Exit o` that first cuts the continuation stack back to its depth when the macro was entered, so nothing the macro left pending runs. `ForRange`, `ForEach`, `ForEachMap` and `Repeat` gain a `break` input wired to `Leave done`, replacing the `state`-flag workaround. A `break` from inside a nested loop or a `Sequence` drops their continuations too. The compiler records the depth in a hidden local when the macro is entered (`cont.depth`) and cuts back to it at `Leave` (`cont.trunc`); the chain-end analysis (`W0302`) follows the same depths. | 3.3, 3.4, 4.2, 5.4 |
| `Mode::Chase` | An enum value is written with `::`, which never starts a pin reference, so the rule that a node may not share an enum's name (`E0102`) is gone and the reading of `.b <- Mode.Chase` no longer depends on which nodes exist. The dotted spelling is still read where it cannot be a wire, and the formatter rewrites it. `wiretc run`, the debugger and the editors' menus show values the new way. | 2.1, 2.3 |
| Implied output on declared nodes | Draft 0.11 let an inline node leave out its one output; a wire from a declared node may now do the same, `.value <- hp` for `hp.value`, as `entry -> loop` leaves out a lone exec output. Wires from `Entry` and from macro nodes keep the name, which is a parameter or result. A node with several outputs still names the one read, and a bare name that is no node is reported as `E0101` rather than making the file unreadable. | 2.3, 2.5 |
| Contextual keywords | A keyword is a keyword only where its statement can start. A word next to `.` or before a single `:` is always a name, a class field may be called `func`, `event` or `dispatcher`, and a node may be called `box`, `at` or `size`. Only `true`, `false` and `null` are reserved; renaming in the editors follows. Syntax highlighting, on the desktop and on the web page, colours a keyword only where it is one. | 2.1 |

**Not adopted.** Annotating each unwired exec output, in `wiretc view --flow` and the editors, with the node it resumes, was proposed alongside `Leave`. It is left for when the editors show continuations at all.
